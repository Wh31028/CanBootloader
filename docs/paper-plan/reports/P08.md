- P01의 END ACK 직후 측정 경계는 P01 sender에 대한 기록이다. P04에서 실제 실행한 P02 entry sender의 elapsed 경계와 동일하다고 간주하지 않는다.

- P05 보고의 validation 링크는 옛 `p05-20261009`를 가리키고 시간 설명은 의도한 경계다. 현재 검증 파일은 [보정 후 validation JSON](../../../experiments/ksma-2026/analysis/p05-terminal-probe-v1-20261009/p05-validation.json)이며 실제 시간 해석은 위 경계다.
- `p05_analyze.py` 상단 docstring의 Custom run 이름도 보정 전 이름이다. 실행 기본값은 보정 후 이름이며 아래 재현 명령에서는 두 run을 명시한다. source/evidence 보존 범위이므로 이번에 script는 수정하지 않았다.

## 발표 핵심 3개와 이후 연구 인계

1. 같은 F407·64 KiB·500 kbit/s direct-write 조건에서 bitmap 선택 재전송·terminal probe와 ISO-TP 기반 application block 재시도를 비교했다.
2. 유효 240건은 양 방식 모두 120/120 OK다. 0.1%의 Custom/ISO-TP 평균 raw elapsed는 9.484/26.448 s, 재전송 overhead는 0.091/3.351%이며 보정 전 10 timeout은 별도 실패 이력이다.
3. 시간은 JUMP 송신 호출까지 포함한다. software omission·DATA/CF 비대칭·별도 batch 조건의 구현 비교이며 일반 신뢰성·ISO 표준 전체의 우위를 뜻하지 않는다.

main TW-03은 학회 작업 후 별도 사용자 요청으로 원래 C sender/target의 bounded retry/deadline·응답 검증·실패 기록을 재검토할 후보로 인계한다. 논문 branch 전체 merge를 지시하지 않는다. 졸업논문 확장 후보는 F103 build/pacing 정합화, image-size 확대, ACK/FC·burst loss, 혼합 트래픽·다중 ECU, 전원 차단·staging/rollback/서명이다. 모두 이번 P08에서 실행하지 않았다.

## 종료 검증 기록

- `Import-Csv`로 P05 summary를 읽어 원고 표 4행의 평균·SD·overhead를 invariant culture 소수 셋째 자리 문자열과 대조했다. 요약문 ISO-TP 양 끝 조건의 평균·CI, 양 원고의 동일 제목·run ID·JUMP 경계·boot 상태·실패 기록 문구도 확인했다.
- 문서 6개를 엄격한 UTF-8 decoding으로 읽고 정규식으로 추출한 로컬 링크에 `Test-Path -LiteralPath`를 적용했다. handoff는 현재 지시 부분을 검사했다. 현재 링크 46개가 존재하며, 문서 전체에 줄 끝 공백은 없었다.
