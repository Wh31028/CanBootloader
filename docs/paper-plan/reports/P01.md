## 먼저 알아둘 말

- **CAN frame(프레임)**: CAN 버스에서 한 번에 주고받는 짧은 메시지다.
- **ACK / NACK / ERR**: 각각 “정상 수신”, “일부 데이터가 빠짐”, “처리 중 오류”를 뜻하는 응답이다.
- **ISO-TP**: 긴 데이터를 여러 CAN frame으로 나누어 보내는 규칙이다.
- **FC(Flow Control)**: 받는 쪽이 보내는 쪽에 “한 번에 몇 frame을 보내도 되는지” 알려 주는 ISO-TP 메시지다.
- **DLC**: 한 CAN frame 안에 실제 데이터가 몇 바이트 들어 있는지 나타내는 값이다.

## 변경

- 시간은 컴퓨터 시간이 바뀌어도 영향을 덜 받는 `time.monotonic()`으로 잰다. START frame을 보내기 바로 전부터 END ACK를 받은 바로 뒤까지가 측정 시간이다. 부트로더로 들어가기 위한 대기와 JUMP 명령 전 0.5초 대기는 빼고 잰다.
- 아래 항목을 따로 기록한다. `send_attempts`는 보내려 한 횟수, `software_drops`는 시험을 위해 일부러 보내지 않은 횟수, `socket_send_success`는 Linux가 CAN 전송 요청을 받아들인 횟수, `send_errors`는 전송 요청이 실패한 횟수다. `protocol_rx`는 형식이 맞는 응답을 받은 횟수다. `retransmit_attempts`와 `retransmit_send_success`는 다시 보내려 한 횟수와 그중 Linux가 받아들인 횟수다.
- Linux가 전송 요청을 받았다고 해서 frame이 실제 CAN 선로에 나갔거나, CAN 장치가 자동으로 몇 번 다시 보냈다는 뜻은 아니다.
- 재전송 비율은 `다시 보내려 한 횟수 / 전체 전송 시도 횟수 × 100`으로 계산한다. Custom 방식의 선택 재전송과 ISO-TP 방식의 블록 재시도만 재전송으로 센다.
- Custom 응답은 표준 CAN ID `0x101`만 받는다. ACK/ERR는 DLC 2, NACK는 DLC 8이어야 한다. ACK의 성공 값도 0인지 확인한다.
- ISO-TP 응답은 표준 CAN ID `0x7e8`과 DLC 8을 확인한다. 처음 받는 짧은 응답(SF)의 길이와 명령도 확인한다. FC는 “계속 보내도 됨”을 뜻하는 CTS(`0x30`)이고, BS=8(8개 frame마다 다시 허가를 받음), STmin=0(추가 대기 시간 없음)일 때만 받는다. 256바이트 단위의 펌웨어 조각과 BS=8은 서로 다른 값이다.
- ID·길이·형식이 맞지 않는 응답은 `invalid_protocol_rx`에 기록하고 성공으로 처리하지 않는다.
